MVP blueprint · handoff package

DGTL Pass

Branded day, monthly, yearly and VIP lifetime passes, sent by email and SMS, added to Apple Wallet, and checked at the door from any iPhone or Android browser. The QR code only points to the pass; the server decides every time.

The architecture call

A module of the Growth Platform, not a new app.

The first draft proposed a separate Next.js + Supabase stack. The platform already runs almost everything a pass system needs. A second stack would duplicate it and put the pass holder in a different database from the lead and the tenant, which blocks the funnel → checkout → pass path.

Passes ship as platform/lib/passes/, a ninth admin tab, a /scan web app and a public pass page. There are no new services.

Two phones scanning one single-use pass in the same second admit exactly once. The row lock serialises them, and a use_count ≤ max_uses check backs it up in the database. A retried scan returns its original verdict. Only a hash of each code is stored, so a leaked database can't mint working passes. If the network drops, the scanner says so and admits nobody.

Decisions already made

Settled, so the build doesn't reopen them.

  • Platform module, not a standalone Supabase app.
  • Team scoping in the app layer, like every other module, proven by isolation tests. RLS later.
  • Postgres only for passes. Atomic redemption needs row locks.
  • Codes are derived, only hashes stored, so a leaked database can't produce passes.
  • Expired, used and scheduled are computed from the window and counters, with no cron job.
  • Online-only scanning that fails closed. Offline is a later, separate model.
  • Scanner is a web app with zxing-wasm, because iOS Safari has no native barcode API.
  • One DGTL Apple Pass Type ID, with each tenant's name on its own passes.
  • Invite-only Google sign-in for staff, linked by Google's account id.
  • Every pass is a branded DGTL card: DGTL⚡ PASS lockup and gold spark on every tier, plus a distinct tier colour.
  • VIP invitation reveals the QR on accept. The offer only shows with consent on file.
  • No email without a postal address and preferences link, as sender identification requires.
Open questions for Stephen

Four answers unlock the build.

Pass host

Every QR code will carry this address, so it can't change later. Recommended: pass.dgtlmag.com.

Apple Developer

Is DGTL enrolled as an organisation? Wallet signing needs a Pass Type ID certificate. Enrolment can take days.

Pilot tenant

Which venue or community goes first? Its timezone, late-night cutoff and postal address go into config.

Sales role

Should front-of-house sales staff issue and scan passes (the current default), or only dedicated issuers?
